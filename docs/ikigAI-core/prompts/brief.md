# /brief — the daily morning brief

> Lands at 07:30. Reads the corpus. Surfaces what compounds, what's drifting, what's worth your attention today.

The brief is the operation that justifies all the other operations. Without a daily reading of state, captures pile up unprocessed and compounding stays invisible. With it, the user wakes up to a one-page read on where their thinking actually is.

Generated by THE HERALD daemon. Written to `output/briefs/<date>.md` and pushed to user via configured channel (initially: open in PWA when first opened that morning; eventually: phone notification).

---

## Inputs

1. **Yesterday's captures** — what the user fed in.
2. **Yesterday's outputs** — what the system produced.
3. **Yesterday's applied actions** — what the user actually did with the system's outputs.
4. **The full canonical corpus** — current state of knowledge.
5. **`me/CLAUDE.md`**, **`me/ikigai.md`**, **`me/lexicon.md`**.
6. **Calendar** — today's schedule, tomorrow's.
7. **`state/feedback.jsonl`** — recent retrieval surface/use signals.
8. **Debaiser candidate flags** — concepts that are due for a contrarian pass.
9. **Drift signals from lens-checker** — terms whose corpus usage has drifted.

---

## Output structure

The brief is structured. Always the same sections, in the same order. The user learns to read this format quickly.

```markdown
# Brief — <Day, Date>

## Overlap state
<Where the framework is lighting up. Region pill counts, intersections most reinforced this week. Lead with this — not progress percent. The whole product is this view.>

## Drift signal
<If the lens-checker has flagged drift in any load-bearing term: surface here. If sovereignty has drifted in usage from your defined lens, surface specifically. If no drift, "no drift detected this week." Do not skip the section. Drift visibility is constitutional.>

## What you fed in
<2-3 sentences. The volume, the texture, what regions yesterday's captures lit up. Not a list; a read.>

## What the system did
<2-3 sentences. The retrievals, the outputs produced, anything significant about pattern.>

## What you applied
<1-2 sentences. Of yesterday's outputs, what did you actually do with them. If nothing, say so. If a lot, name the top 1-2.>

## Compounding visible
<This is the active surface. 2-3 specific things that compound across regions or projects:
  - "Yesterday's capture on X reinforced concept Y, which is load-bearing for project Z. Z hasn't seen new input in 12 days."
  - "Two captures yesterday lit up [centre]. If you stay on this track, you're consolidating the centre case for IkigAI itself."
  - Specific page_ids referenced. Specific ripples.
This section is what makes the brief worth reading. Without this, the brief is administrative. With this, it's the framework overlay made visible for the day.>

## Today's options
<3 stage options across active projects, with explicit ring/region lighting:
  - "S2 component X — 1.5h — lights tooling/sovereignty(data)/profession"
  - "Phase 1 of idea Y — 2h — lights mission/centre, calendar slot 10am-12pm available"
  - "Capture review and lexicon update — 30m — lights principle/narrative-sovereignty, pulls drift back"
The brief recommends one with reasoning, but does not insist. The user picks.>

## Recommendation
<one paragraph: which option lands best given current state, why, what it compounds with. Honest. Always reasons explicitly so the user can disagree.>

## Calendar offer
<If recommendation has natural calendar fit, propose a slot. If not, "no calendar offer; user to schedule.">

## Debaiser candidate
<If keeper daemon flagged a concept as debaiser-due: surface here. "Concept X has been reinforced 7 times in 30 days without contradiction. Want to run /debaiser X?" User can accept, defer, dismiss.>

## Open in the inbox
<count of unprocessed inbox items, top 1-2 by recency or estimated weight. "12 items in inbox; 2 voice memos from last night.">

## Yesterday's outputs awaiting application
<list of unapplied outputs from prior 7 days. "Phased plan for Y from 3 days ago, no calendar slot accepted yet. Want to revisit?">
```

---

## Voice

The brief is one of two operations that the user reads daily (the other being whatever they capture). It must:

- **Lead with the framework state**, not the to-do list.
- **Be matter-of-fact**. No motivation. No "you've got this." No emoji.
- **Name pages explicitly**. The user can click through to source.
- **Reason for every recommendation**. The user is the thinker; they need the basis to disagree.
- **Honour today's calendar reality**. Don't propose a 4h block at 9am if the user has a meeting at 10.
- **Acknowledge zero-state honestly**. If yesterday was empty, say so plainly. Don't manufacture content.

---

## Length budget

The brief is one page on a phone screen. Total length: 350-600 words. Each section: 1-3 sentences except "Compounding visible" (which can stretch to 5-6 if the day is rich) and "Today's options" (which is bullet-structured and counts as ~80 words).

If the brief is exceeding 600 words, the system is over-explaining. Cut.

---

## Cadence

Generated 07:00. Available 07:30. Decay: a brief older than 24h is archived; the user shouldn't be re-reading yesterday's brief.

The user can request a brief at any time via MCP — `/brief now` returns the brief with current state regardless of cadence.

---

## What the brief refuses to do

- Tell the user what to do. Recommendations are reasoned and optional.
- Hide drift. Lens-checker findings appear before recommendations.
- Pretend yesterday was busy when it wasn't.
- Suggest work that doesn't fit calendar reality.
- Skip "Compounding visible" — even if the day's specifics are thin, this section anchors the brief in the framework. If there's genuinely nothing to surface, write one sentence: "no fresh ripples; the corpus is consolidating, not expanding."
